Retries and timeouts

Every call to the sync service is retried. By default a call is tried up to five times (maxAttempts), waiting a little longer before each new try.

How a call is retried

The delay doubles on each try, starting at baseDelayMs and never going past maxDelayMs. A random part (jitter) keeps many clients from retrying at the same moment. If the server sends a Retry-After header, that wins.

The client

pull fetches changes made elsewhere and push sends yours. Both are wrapped in withRetry, and both give up on a single try after timeoutMs.

Options

OptionDefaultWhat it does
maxAttempts5How many times a call is tried in total.
baseDelayMs250Delay before the second try.
maxDelayMs8000The longest single delay.
timeoutMs30000How long one try may take.

Set maxAttempts to 1 to turn retries off, for example in tests. timeoutMs applies to each try, not to the whole call.

Checking your setup

The check makes one pull and one push against the service and prints every retry.

On your machine

export SYNC_TOKEN=<your token>
npx tidepool sync --check

In CI

npm ci
npx tidepool sync --check
npm test
